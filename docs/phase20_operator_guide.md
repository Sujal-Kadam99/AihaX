# AihaX Phase 20 — Operator Guide: Real-World Hunting Intelligence & Review Workflow

## Overview

Welcome to the **AihaX Phase 20 Operator Workflow**. Phase 20 upgrades AihaX into an operator-assisted hunting intelligence platform designed for high-value bug bounty assessments (e.g. HackerOne programs).

This guide walks human operators through managing targets, reviewing prioritized recommendations, inspecting evidence, and producing certified submission packages.

---

## 1. Setting Up an Authorized Hunting Campaign

1. Navigate to **Campaigns** in the AihaX Web UI.
2. Select your authorized program scope (e.g., `*.xiaomi.com`).
3. If the scope contains wildcards, the campaign initializes in `WAITING_FOR_TARGET` state.
4. Provide a concrete target URL (e.g., `https://account.xiaomi.com`) to bind the target and generate an authorized execution plan.
5. The campaign profile automatically locks to:
   - **Request Budget:** 10 requests max
   - **Concurrency:** 1 (Single threaded)
   - **Rate Limit:** 2 RPS
   - **Allowed Methods:** GET, HEAD, OPTIONS

---

## 2. Navigating the Hunting Recommendation Queue

1. Open the **Hunting Queue** tab (`/hunting`).
2. The queue presents ranked, prioritized check recommendations generated by the `HuntingIntelligenceEngine`.
3. Each recommendation card details:
   - **Check Name & ID** (e.g., `C065: Cleartext HTTP Transmission Check`)
   - **Category & Risk Level** (e.g., `TRANSPORT`, `SAFE_ACTIVE`)
   - **Target Endpoint & Method** (e.g., `GET https://account.xiaomi.com/`)
   - **Utility Score & Rank** (e.g., `Score: 0.78 #1`)
   - **Request Cost** (e.g., `1 req`)
   - **Historical Context & Decision Rationale** (derived from past campaign yield and cross-assessment memory)
   - **Expected Evidence Contract** (what status codes, headers, or byte signatures verify or refute the check)

---

## 3. Reviewing and Acting on Recommendations

All recommendations default to `HUMAN_REVIEW_REQUIRED`.

When reviewing a recommendation, you have five audited actions:

| Action | Meaning | Impact |
| :--- | :--- | :--- |
| **Approve** | You confirm the check is safe, in-scope, and valuable. | Launches a safe single-request execution. Deducts request cost from the 10-request budget. |
| **Reject** | You decide the check is irrelevant or unpromising for this target. | Logs rejection reason in memory and penalizes check utility for future runs. |
| **Skip** | You want to defer the check without penalizing its score. | Keeps check available for later review. |
| **Already Tested** | You verified the check was already tested out-of-band. | Suppresses check on this target and logs verification note. |
| **Request Re-Verification** | You want the check re-evaluated under stricter conditions. | Dispatches targeted verification request with evidence capture. |

> **Safety Gate Modal**: Clicking **Approve** opens a confirmation modal displaying the target URL, HTTP method, and budget impact. You must tick the confirmation box before execution proceeds.

## 4. Evidence Inspection & Finding Quality Bands

Once a check completes, review findings in the **Findings** tab or **Evidence Vault**:

1. **Quality Band Breakdown**:
   - **Band A (>= 0.90)**: Gold standard reportable finding with byte-level HTTP proof and confirmed impact.
   - **Band B (0.75 - 0.89)**: Strong finding with verified request/response.
   - **Band C (0.60 - 0.74)**: Acceptable minimal finding.
   - **Band D (< 0.60)**: Non-reportable candidate (missing proof or speculative).
2. **Fact vs. Inference Separation**:
   - Review **Confirmed Impact** (observed facts from server response).
   - Review **Potential Impact** (marked with `[INFERENCE]` tag).
3. **Cryptographic Hashes**:
   - Check the `proof_request_sha256` and `proof_response_sha256` values to verify evidence integrity.

---

## 5. Generating HackerOne Submission Packages

1. Navigate to **Reports** (`/reports`).
2. Select your campaign and click **Generate Report Package**.
3. AihaX generates a multi-format package:
   - **HackerOne Markdown (`report.md`)**: Ready-to-copy markdown with clean reproduction steps, observed impact, and zero placeholder text.
   - **Audit-Sealed PDF (`report.pdf`)**: Executive and technical printable artifact.
   - **Structured JSON (`report.json`)**: Machine-readable finding DTOs.
   - **Cryptographic Package Seal (`package_hash`)**: 64-character SHA-256 seal anchoring all findings and audit events.
