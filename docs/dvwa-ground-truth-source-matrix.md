# DVWA Ground-Truth Source Matrix

## Scope and source pin

This is a **source-derived benchmark oracle**, not a scan result. It records what the vulnerable exercise implementations do so later local runs can be scored against explicit expectations. A source-level unsafe pattern is not, by itself, proof that AihaX can reach or exploit it at runtime.

- Source: official `digininja/DVWA` repository, commit `068d974487a297c155c48722f9fcf7180a83adc4` (snapshot reviewed 2026-10-09).
- Four levels are `low`, `medium`, `high`, and `impossible`; behavior is module-specific.
- `SOURCE_RISK`: source has an unsafe sink or partial filter that the exercise is intended to expose. Runtime still needs a bounded proof.
- `SOURCE_CONTROL`: source shows the intended defense for that module. This does not certify the entire DVWA instance or other checks.
- `CONDITIONAL`: result depends on session state, another capability, endpoint configuration, or runtime normalization; do not score a simple positive/negative until confirmed.
- `NOT_COVERED`: this DVWA module does not provide ground truth for that AihaX check. It must be tested with a separate fixture or remain unscored.

## What this does and does not score

This matrix gives a source-based oracle for 12 module/check groups covering 15 of the 86 registry IDs. It does **not** establish runtime positives, browser execution, server configuration, exact request/response behavior, or that the merged AihaX build detects the issue. The control cases also do not certify DVWA's entire Impossible level as secure.

The remaining registry checks must not be scored as true negatives from DVWA simply because no corresponding exercise is present. The 71 IDs currently outside this matrix are: C001, C002, C003, C004, C005, C006, C008, C009, C010, C011, C012, C013, C014, C015, C016, C017, C018, C019, C020, C021, C025, C028, C029, C030, C033, C034, C035, C036, C039, C041, C042, C043, C044, C045, C046, C049, C050, C051, C052, C053, C054, C056, C057, C058, C059, C060, C061, C062, C063, C064, C065, C066, C068, C069, C070, C071, C072, C073, C074, C075, C076, C077, C078, C079, C080, C081, C082, C083, C084, C085, C086. In particular, this source matrix does not ground truth TLS/certificate configuration, DNS/subdomain takeover, SSRF, OAuth, GraphQL, WebSockets, request smuggling, races, cache poisoning, or the broader misconfiguration and sensitive-data checks. Add local fixtures for those checks or mark them `NOT_COVERED` in the benchmark report.

## Benchmark scoring contract

When the local campaign runner is available, record each check × module × level as one of:

- `TP`: expected source risk and claim is independently proven by check-specific request/response evidence.
- `FP`: claim is reported without satisfying that module's proof condition.
- `FN`: source risk is reachable under the tested account/session and request, but the check misses it.
- `TN`: the check ran with its prerequisites satisfied and no claimed condition exists for that module/level.
- `NOT_TESTED`: a prerequisite, tool, endpoint, account, or safety gate prevented the check.
- `NOT_COVERED`: the DVWA module does not represent the check.

`NOT_TESTED` and `NOT_COVERED` are never counted as true negatives. Preserve the DVWA security cookie, auth/session state, form method, required token, and module endpoint for each run. Reset stored state between runs. Never compare only aggregate finding totals.
